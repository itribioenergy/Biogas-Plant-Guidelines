# v1.1 圖像化改版任務（使用者回饋）

## 回饋背景
v1 已有封面+20頁內容、網頁、PDF、DOCX；但視覺過於陽春、像以文字為主的網頁排版，**不符合原定「AI生成主視覺、吉祥物引導、易懂圖解」的手冊定位**。應保留內容與程式基礎，重新建構主要視覺。

## 明確優先序
1. 將使用者已提供的官方吉祥物兩張原始 PNG 真正提交至 `assets/mascot/reference/`，驗證 SHA-256。若無法讀取附件，請明確阻擋該步驟，而非以自製替代角色充數。
2. 用圖像生成工具基於**原始參考圖**製作同一吉祥物的單獨透明背景姿態；優先提取/使用已有八姿態，後續新姿態需檢查頭盔葉片、臉部、眼睛、胸章、身體比例、主色。
3. 規劃視覺資產清單與頁面對應表；優先產出約 8–10 張真正具情境的設備核心插畫（例如全場鳥瞰、厭氧槽剖面、進料、脫硫、儲氣袋、管路積水、發電機、警報等）；其他頁使用圖裁切／局部對照／視覺模組重用。
4. 每張核心插畫遵守已定風格：溫暖親民、2D/輕等角視角、乾淨扁平向量感、可靠的工業設備外觀；**避免只用單調的 SVG outline 假裝完成視覺設計**。
5. 圖片中不燒錄需要精確的中文字、數字或箭頭：AI 主要生成背景與設備場景，中文標籤/數字/警語由 HTML/SVG 排版程式疊加，確保正確及可編輯。
6. 建立視覺品質門檻：封面需具有設計感；P03 用全場主流程插圖；P05 厭氧槽異常對照；P06 產氣下降決策流程；P09 氣袋狀態；P10 脫硫塔與量測點；P11 積水示意；P13 發電機標註。每頁至少一個易理解的視覺核心，避免整頁純文字。
7. 建立 master character sheet、角色的姿態 atlas、設備插圖主圖，並輸出網頁/PDF/DOCX（同一素材源）；對整本書做視覺一致性/可讀性回歸檢查。

## 技術與安全界線
- 所有設備插圖是溝通示意而非工程施工圖；閥件、管線和取樣點應工程複核。
- 危險情境不得使用誤導的歡笑吉祥物；H2S及可燃氣體警示須清楚。
- 避免在不確定的情況下畫出具體維修步驟。
- 如果生成能力、素材附加權限或 GitHub binary 上傳受限制，將阻礙紀錄在 `docs/`，不要宣稱已達到圖像版。

## 出版策略
保留 v1 討論稿。v1.1 另行輸出，檔名不覆蓋既有版本。可先製作「封面+P03+P05+P10」四頁定稿樣板，確認風格，再批次擴展到 20 頁；若使用者已明確要求直接完成，可自行採用樣板後續執行。
